Frequently Asked Questions

WIF is a Base58Check-encoded format for private keys. It includes a version byte (0x80 for mainnet), the 32-byte private key, an optional compression flag (0x01), and a 4-byte checksum. Keys starting with 5 are uncompressed, while K or L indicate compressed keys.

Hash160 is the combination of SHA-256 followed by RIPEMD-160: RIPEMD160(SHA256(x)). It produces a 20-byte (160-bit) hash and is used in Bitcoin to create shorter addresses from public keys. The result is then encoded with Base58Check to create a Bitcoin address.

A public key on secp256k1 is a point (x, y). Uncompressed format is 04 + x + y (65 bytes). Compressed format is 02/03 + x (33 bytes), where 02 means y is even, 03 means y is odd. The y coordinate can be derived from x. Compressed keys produce different addresses than uncompressed keys from the same private key.

Base58Check is Base58 with a 4-byte checksum appended. Base58 excludes similar-looking characters (0, O, I, l) to prevent transcription errors. The checksum is the first 4 bytes of SHA256(SHA256(data)). It's used for Bitcoin addresses, WIF keys, and extended keys (xpub/xprv).

Bech32 (BIP-173) is the encoding for SegWit v0 addresses (bc1q...). It uses a 32-character alphabet and has strong error detection. Bech32m (BIP-350) is a modified version for SegWit v1+ (Taproot: bc1p...). The difference is a single constant in the checksum algorithm.

Keccak-256 is the original Keccak hash before NIST standardized it as SHA-3 (with padding changes). Ethereum uses Keccak-256 (not SHA-3) to derive addresses: take the last 20 bytes of keccak256(uncompressed_pubkey_without_04_prefix), then prefix with 0x.

EIP-55 adds a checksum to Ethereum addresses using letter case. The address is hashed with Keccak-256, and each hex character is uppercased if the corresponding nibble in the hash is ≥ 8. This allows detection of typos while keeping addresses the same length. Example: 0xDEAD8A20... vs 0xdead8a20....

BIP38 is a standard for encrypting Bitcoin private keys with a passphrase, producing a string starting with 6P. It uses scrypt (N=16384, r=8, p=8) for key derivation and AES-256-ECB for encryption, with the address hash as a salt so two people with the same passphrase produce different ciphertexts. This calculator implements the non-EC-multiply mode (flag 0xC0 uncompressed / 0xE0 compressed). Decryption is slow by design — typically 1-5 seconds — to resist brute-force attacks.

Bitcoin: Private key → Public key (secp256k1) → Hash160 → Base58Check (legacy) or Bech32 (SegWit).
Ethereum: Private key → Uncompressed public key → Keccak-256 → Take last 20 bytes → Add 0x prefix → Apply EIP-55 checksum.

SegWit (P2WPKH): bc1q... - Uses Hash160 of compressed public key, encoded with Bech32.
Taproot (P2TR): bc1p... - Uses x-only public key (32 bytes) with a tweak, encoded with Bech32m. Taproot enables advanced scripting and improved privacy.

Bitcoin uses little-endian byte order internally (least significant byte first), but displays data in big-endian (most significant byte first). When analyzing raw Bitcoin data (transactions, block hashes), you often need to reverse the byte order to match displayed values.

Bitcoin uses SHA256(SHA256(x)) for block hashes, transaction IDs, and checksums. This provides protection against length-extension attacks that affect single SHA-256. It also adds computational cost for proof-of-work mining without requiring a different hash function.
